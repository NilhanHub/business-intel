# 1BT Service Taxonomy

`D:\gaps\Business_Intel\sl_trigger_leads\data\onebt_service_taxonomy.json`

The app must use this local taxonomy instead of reading the 1BT website at runtime.

## staff_augmentation_delivery_capacity

Display name: Staff Augmentation / Delivery Capacity

Use when evidence shows hiring pressure, engineering roles, QA/QE roles, API/integration engineers, backend roles, data roles, AI developer roles, support roles, or multiple open technical positions.

Do not use when evidence is not about delivery capacity, technical hiring, or execution pressure.

Evidence needed: live hiring or role evidence with source URL and excerpt.

Example angle: "We noticed you are expanding your technical team; 1BT can provide near-term engineering capacity while hiring ramps."

## custom_software_development

Display name: Custom Software Development

Use when evidence shows product launch, platform build, app modernization, SaaS build, backend delivery, portals, workflow tools, or new digital products.

Do not use for generic PR, pure support, or strategy-only signals without delivery evidence.

Evidence needed: live evidence of product, platform, app, backend, portal, or software delivery need.

Example angle: "1BT supports custom software/product delivery with AI-accelerated engineering."

## ai_apps_workflow_automation

Display name: AI Apps / AI Workflow Automation

Use when evidence shows AI initiatives, automation programs, AI developer roles, AI pilots, productivity automation, agentic workflows, or intelligent process automation.

Do not use just because AI is fashionable. Require concrete AI, automation, workflow, developer, or implementation evidence.

Evidence needed: live AI or automation activity beyond vague PR language.

Example angle: "1BT helps teams convert AI intent into practical apps, workflows, and automation."

## ai_strategy_consulting

Display name: AI Strategy Consulting

Use when evidence shows board or executive AI strategy, digital transformation agenda, exploratory AI programs, or need for AI roadmap before implementation.

Do not use for concrete engineering roles where implementation capacity is the stronger fit.

Evidence needed: live evidence of strategy, executive intent, roadmap, or exploratory AI activity.

Example angle: "1BT can help turn AI ambition into a practical roadmap and delivery plan."

## data_analytics_ai

Display name: Data Analytics & AI

Use when evidence shows reporting dashboards, analytics products, data workflows, BI, data platforms, customer analytics, or operational insights.

Do not use for generic technology news without data, analytics, dashboard, or insight evidence.

Evidence needed: live evidence of data, reporting, analytics, dashboard, BI, or insight needs.

Example angle: "1BT can support data workflows, analytics, and AI-backed insight systems."

## microsoft_dynamics_365_crm_power_platform

Display name: Microsoft Dynamics 365 / CRM / Power Platform

Use when evidence shows CRM, sales/customer service process, claims/customer support workflows, Microsoft stack, Power Platform, Dynamics 365, ERP/finance/operations, field service, or customer data modernization.

Do not claim Dynamics, CRM, or Power Platform unless evidence names CRM/customer workflow, Microsoft stack, or adjacent operational systems.

Evidence needed: live CRM, customer service, claims, Microsoft stack, ERP, field service, or customer-data evidence.

Example angle: "1BT supports Dynamics 365/CRM discovery, design, implementation, migration, training, support, and ongoing management."

## integrations_api_middleware

Display name: Integrations / API / Middleware

Use when evidence shows API engineers, middleware roles, integration projects, system connectivity, data exchange, ERP/CRM integration, payment/logistics/operations integration.

Do not use when API or integration is absent from the evidence.

Evidence needed: live evidence that explicitly names APIs, integrations, middleware, or system connectivity.

Example angle: "1BT can help stabilize and accelerate integrations, APIs, and middleware delivery."

## managed_application_it_support

Display name: Managed Application / IT Support

Use when evidence shows support load, application support hiring, production systems, operations support, customer support tooling, or need for ongoing platform management.

Do not use for build-only or strategy-only signals unless support or production operations are evident.

Evidence needed: live evidence of support, production, operations, or ongoing platform management pressure.

Example angle: "1BT can provide managed support for applications, workflows, and business systems."

## cloud_product_development

Display name: Cloud Product Development / AWS / Azure

Use when evidence shows cloud platform build, SaaS scale-up, AWS/Azure requirements, serverless pipelines, deployment modernization, or cloud product engineering.

Do not use for generic web development unless cloud, SaaS, AWS, Azure, serverless, or platform scale is present.

Evidence needed: live evidence of cloud platform, SaaS, AWS, Azure, serverless, DevOps, or scalable product delivery.

Example angle: "1BT can support cloud product development and scalable platform delivery."

## qa_test_automation

Display name: QA / Test Automation

Use when evidence shows QA/QE roles, test automation, API testing, BDD, performance testing, quality engineering, regression testing, or release pressure.

Do not use when quality, testing, QA, QE, or release pressure is absent.

Evidence needed: live evidence of QA, QE, test automation, API testing, or release quality pressure.

Example angle: "1BT can strengthen QA, API testing, automation, and release confidence."

## low_fit_or_watch

Display name: Low Fit / Watch

Use when evidence is real but weak, vague, non-IT, too junior, too general, or not clearly related to 1BT services.

Do not use if another bucket has clear, source-backed evidence.

Evidence needed: a live source exists, but it does not support a confident 1BT opportunity claim.

Example angle: "Do not pitch yet; monitor until stronger operational or technology evidence appears."
